# Changelog: tinyactors-core/bindings/node

What changed in tinyactors-core/bindings/node in each release. The summary of a release
is written for someone upgrading; the lists below it are generated from the
commits and from the public API (docs/adr/0002-changelogs.md).

## [0.2.0] - 2026-10-06

### Summary

This release replaces the package. `@tinyactors/node` 0.2.0 is the Node.js binding built from `tinyactors-core/bindings/node`, and its API is a new one (ea4113b). It is xstate-style: machines from `createMachine` or `setup`, actors from `createActor`, SCXML through `fromSCXML`, compiled systems through `compileSystem` and `loadImage`, and links between systems through `serveLinks`. A few names carry over from 0.1.0 (`createSystem`, `System`, `SystemOptions`, `Actor`, `SendOptions`) with new shapes and meanings.

It installs the same way as 0.1.0: a prebuilt addon per platform (darwin-arm64, darwin-x64, linux-x64, linux-arm64) as an optional dependency, with one Linux addon for glibc and musl, so nothing compiles on install. It runs on Node.js 22.12 or later and on Bun.

The commits listed below from before the replacement changed the 0.1.0 addon, which this release no longer contains.

### Upgrading

- The 0.1.0 API is removed, with no compatibility layer: its system API (statechart definitions, post and send with their results, loaders, the debug adapter, and the tracing and metrics helpers) is gone. Rewrite callers against the xstate-style API: `createMachine` and `createActor` for a machine, `fromSCXML` for an SCXML document (ea4113b).
- `createSystem`, `System`, `SystemOptions`, `Actor` and `SendOptions` keep their names but not their shapes: check each use against the new declarations.
- The changes the 0.1.0 addon went through before it was removed (caf78df, 1d4f458, bb87794, 0bc6cfa, 6a6a1fa, 482417e, 28a0ccb, 19cd181, 904b335, 93c3d46, ccd6d63, bc82ab4, 206cdb4, 3edae90) need nothing beyond that rewrite.

### Breaking changes

- setting the time fires due sends; ta_run reports the next wake (caf78df)
- internal events and invocation names travel as text (1d4f458)
- hosts read event names as text (bb87794)
- hosts pass event names to core as text (0bc6cfa)
- hosts post by address into core; the router goes (6a6a1fa)
- mail for targets that are not resident waits in core (482417e)
- move the OTLP encoder into tinyactors-otlp (28a0ccb)
- mail to resident sessions travels as envelopes (19cd181)
- the taken input stays in its envelope; event blocks go (904b335)
- admit inputs into the envelope pool and run them with ta_run (93c3d46)
- core writes telemetry to a lossy ring stamped by a host clock (ccd6d63)
- send() resolves when its macrostep ended, without until (bc82ab4)
- no input log (206cdb4)
- remove the debug adapter and the VS Code test client (3edae90)
